## Topics

### 1. Group identity, membership and activation — [Overview](https://betterdisplay.pro/guide/interface-reference/settings/groups/), [Individual group](https://betterdisplay.pro/guide/interface-reference/settings/groups/group/)

- **BetterDisplay behaviour** (Free: Default Group/basic brightness; Pro: additional groups, custom activation and priority controls): Settings > Groups opens an Overview and a horizontal group selector; Tools > Groups > Configure Groups reaches the same place. Remember the selected group; permit horizontal scrolling/direction buttons when necessary. Differentiate active, disabled/unavailable, and enabled-but-inactive states, including an activation explanation. Enabling a group does not enable its independent synchronization, layout or scale features.
- Create opens a naming sheet; blank names generate a label, Cancel creates nothing, and successful creation opens the new editor. New custom groups are enabled, use all connected displays, require all configured members, prohibit outsiders and are exclusive. All three group features start disabled. Duplicate copies configuration, suggests a name with a duplicate suffix, allows editing, and starts disabled. The Default Group can be duplicated or disabled but cannot be deleted. Discard confirms removal of the group and all rules, with Cancel preserving them. Names appear in Settings and the menu. Advanced accepts an SF Symbol name, provides a symbol browser, and falls back to the ordinary group icon if unsupported.
- Activation choices: all explicit remembered members connected, with at least one present; any member; at least two members; or suitable participants for enabled synchronization/scale/layout rules. With automatic membership, the all-members rule needs at least one current member. Empty feature entries are insufficient. The guide's participant-based rule has non-obvious precedence: enabling layout requires an actionable layout/main rule even if another feature has a usable pair; a synchronization entry with targets but no accepted source can supersede a prior scale match. Expose the actual reason rather than assuming a simple OR across features.
- Automatic all-connected membership defaults on. Automatic exclusions and an explicit inclusion list are separate saved values; exclusions do not filter explicit membership. Membership survives unplugging. A reveal-absent switch exposes remembered choices; selected absent entries stay visible and removable. Mark absent devices distinctly, explain a completely empty detection result, and allow Option-click identification without changing membership. Per-feature roles are subsets of membership.
- Outsider prohibition and exclusivity default on for new custom groups, off for Default. Evaluate higher priority first: an active exclusive group blocks all lower groups; an exclusive group cannot join an already active higher group. Otherwise multiple non-exclusive groups may coexist. Recompute after topology/settings changes and save sheet edits before Done.
- Show reorder arrows only with at least two custom groups plus Default; the reveal action toggles arrow visibility. Moving saves and recomputes immediately. Default stays last, with boundary arrows constrained to custom positions. Option-selecting a group exposes a numeric priority in Advanced; normalize values into order. Without Pro, custom groups are unavailable and Default is presented first. Overview's startup-layout option defaults off and is independent of the menu's apply-after-group-change option.
- **FreeDisplay today**: 🟡 Partial. CRUD, explicit remembered membership, connected counts and offsets exist in `Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:32`, `Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:70`, `Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:82`, `Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:94`. `Packages/TopologyCore/Sources/TopologyCore/DisplayGroup.swift:14` has only identity, members, brightness/contrast switches and offsets. Creation requires a nonblank unique name, starts empty with brightness sync on (`Packages/TopologyCore/Sources/TopologyCore/DisplayGroup.swift:22`, `Packages/TopologyCore/Sources/TopologyCore/DisplayGroup.swift:86`); adding a member moves it out of any other group (`Packages/TopologyCore/Sources/TopologyCore/DisplayGroup.swift:108`). Delete is immediate (`Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:44`). No Default Group, duplicate, master enable, automatic membership, activation reason/rules, priorities, overlap/exclusivity model or custom icon exists. Settings has no dedicated Groups sidebar section (`Apps/OpenDisplay/Sources/SettingsView.swift:80`). These are semantic gaps, not translation issues.
- **Implementation notes**: L for activation/membership redesign, S for CRUD polish. Use pure TopologyCore evaluation plus SwiftUI persistence and public CoreGraphics observations. Migrate current single-group membership intentionally; do not silently change existing sync behavior. Give activation reasons stable codes; resolve competing writes deterministically. Do not reproduce licensing restrictions. Backlog SO-05/SO-06.
- **Acceptance criteria**:
  - Creating, canceling, duplicating, renaming and deleting preserve the stated defaults and cancellation semantics; duplicate cannot start adjusting displays.
  - Exercise every member-count rule, absent remembered member, outsider and exclusive-priority combination; the displayed reason matches the evaluator.
  - Automatic/explicit list switching preserves both lists; identification changes no selection; changing priority immediately recomputes active groups.

### 2. Synchronization controls and routing — [Synchronization](https://betterdisplay.pro/guide/interface-reference/settings/groups/group/synchronization/)

- **BetterDisplay behaviour** (Free: Default Group general Brightness, delta/range and external-change options; Pro: custom-group sync, other built-in controls, nits, external/main source filters and editing individual inclusion/exclusion entries): Settings > Groups > group > Synchronization has a master switch, initially off, and independent per-control enable switches. Add lists custom controls first, then built-ins by family; configured/unavailable entries cannot be added again. A new entry starts enabled and opens its editor; warn if the master is off. Back returns to the list; removing an entry requires confirmation and deletes its settings.
- General Brightness selects each participant's appropriate combined/hardware/software controller. An all-image-adjustments entry covers the registered family and maps brightness appropriately; a specific entry overrides a broad one. Other entries include volume, mute, hardware contrast, saturation, RGB gain, black level, individual software adjustments and filters. Option-selecting the group reveals separate combined/hardware/software brightness entries. A menu choice does not prove controller support.
- Delta defaults on: send the change, preserving existing differences until clamping. Range remapping defaults on: translate either an absolute fraction of source range or a delta fraction into the target range. Turning delta off copies absolute levels; turning remapping off uses controller values directly. Boolean controls copy state. General brightness can instead match calculated nits; effective nits mode hides delta/range fields. Accurate luminance ranges and target capability are prerequisites; the page does not state a nits-toggle default or promise physical calibration.
- External changes default off; when enabled, a second external-only option (also initially off) can suppress app-origin changes. Detectable ambient-sensor, Touch Bar, Control Center and integration changes can lead. Undetectable changes cannot. Reconfiguration can seed absolute/nits rules from supported Apple auto-brightness, so reconnecting may change brightness without a slider gesture. Shift on menu sliders/toggles bypasses synchronization once. All-display keyboard brightness or audio operations bypass the corresponding sync to avoid duplicate application. Prevent feedback loops per originating operation.
- Any-member sources default on, virtual sources off, with optional exclusions. Manual source mode combines external, Apple, main, and specified-list filters with AND; no filter means any member. External excludes built-in and app-managed virtual displays. All-member targets default on; virtual targets and HDR/reference-XDR skipping both default off. Optional exclusions apply only in automatic mode. Explicit target lists bypass those automatic virtual/HDR exclusions. Only connected members with a usable controller receive changes.
- Source/target editors are limited to members, support remembered absent entries and explicit empty-state messages, retain selected absent entries, and offer nonmutating Option-identify. Row switches save immediately; no Apply.
- **FreeDisplay today**: 🟡 Partial. Brightness fan-out uses a learned group baseline plus per-display offsets, not selectable delta/absolute/range semantics (`Packages/TopologyCore/Sources/TopologyCore/GroupSyncPolicy.swift:268`, `Packages/TopologyCore/Sources/TopologyCore/GroupSyncPolicy.swift:298`, `Packages/TopologyCore/Sources/TopologyCore/GroupSyncPolicy.swift:328`). Contrast copies a level to capable followers (`Packages/TopologyCore/Sources/TopologyCore/GroupSyncPolicy.swift:344`). The UI exposes only brightness, contrast and offsets (`Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:52`, `Apps/OpenDisplay/Sources/DisplayGroupsCard.swift:102`). App writes use native/private brightness, private DDC or software dimming (`Apps/OpenDisplay/Sources/AppModel.swift:1540` (`applySilentBrightness`)); native brightness is polled automatically whenever group sync is active (`Apps/OpenDisplay/Sources/AppModel.swift:1448`). There is no external-change opt-out, origin-only mode, nits calibration, general control registry, source/target filter UI, independent master, or Shift bypass. Echo tokens and skipping absent/governed members are implemented. Learned offsets are valuable existing behavior but do not establish BetterDisplay delta parity.
- **Implementation notes**: M for free brightness semantics; L for arbitrary-controller and nits sync. Pure policies should carry origin, transaction ID, controller range and explicit bypass. Public gamma/overlay sinks can support the free workflow; physical backlight requires DisplayServices SPI or IOAVService DDC here. Nits estimates need provenance, clamping and calibration; never label percentage equality as measured luminance equality. Backlog SO-05/SO-07.
- **Acceptance criteria**:
  - Unequal initial levels distinguish delta from absolute mode; unequal configured ranges distinguish remapped from raw values; boundary clipping never loops.
  - Explicit targets are not accidentally filtered by automatic exclusions; source filters combine conjunctively; absent/unsupported members are skipped with a reason.
  - Outside-change off/on/only, Shift bypass and all-screen bypass each produce exactly the intended writes; nits mode hides incompatible fields.

### 3. Relative layout protection — [Layout Protection](https://betterdisplay.pro/guide/interface-reference/settings/groups/group/layout-protection/)

- **BetterDisplay behaviour** (Pro): Settings > Groups > group > Layout Protection has an initially-off feature switch. Position rules require an active group and two connected members with independently movable desktops; ordinary mirror targets cannot be positioned independently. Add omits already-configured display/orientation combinations. A new rule is enabled but inert until reference and direction are selected. Directions are physical left/right/above/below, including in RTL UI, with centered adjacent edges initially.
- Each rule has its own enable switch and warnings for disabled group protection, missing display or undefined relationship. Reference menus label disconnected members; clearing selection removes reference, Cancel preserves it, and direction can also be cleared. Option-click a rule or reference identifies a display without editing/selecting it. Option-selecting a group exposes portrait/landscape-specific creation in addition to any-orientation rules. Matching specific rules outrank general rules; even a disabled specific entry can mask the general rule for that orientation.
- Anchor editing reveals two sliders, a scaled preview and live edge markers. Side-by-side anchors move top/bottom; stacked anchors move left/right. Align anchors in logical desktop coordinates. Labels express distance from the nearer edge (center 50%, edge 0%); show millimeters if dimensions exist. Physical dimensions improve the picture/labels but do not replace logical bounds. Correct dimensions in display additional settings. Snap near center unless Option is held at completion. Hiding the editor preserves offsets; reset by centering both. Warn if the preview orientation differs from the rule. Remove markers on leaving editor/closing Settings.
- Main-display protection selects one connected member or an unspecified state; unspecified leaves main choice to macOS/device protection. Option-identify is available. Apply All executes actionable rules across all active groups, although the Settings button is disabled when this group's master is off. Higher-priority groups win conflicts for a display, opposing pairs are not both applied, overlaps may reposition other displays, and successful results become system configuration.
- Reapply after relevant mode/topology changes; startup application is a separate initially-off Overview option, and menu-triggered group changes have a separate auto-apply preference. Disabling/deleting protection does not undo the current layout. Rule removal confirms the named display and orientation. Immediate move commands and device configuration protection remain distinct features.
- **FreeDisplay today**: 🟡 Partial. Settings > Arrange supports drag arrangement and protected snapshots (`Apps/OpenDisplay/Sources/SettingsView.swift:150`, `Apps/OpenDisplay/Sources/SettingsView.swift:174`, `Apps/OpenDisplay/Sources/SettingsView.swift:198`). Protection is keyed by display-set fingerprint (`Packages/TopologyCore/Sources/TopologyCore/LayoutProtection.swift:145`) and handles launch/wake/topology triggers (`Packages/TopologyCore/Sources/TopologyCore/LayoutProtection.swift:26`), a three-second debounce and two-attempt cap (`Packages/TopologyCore/Sources/TopologyCore/LayoutProtection.swift:133`). It protects complete modes/origins/main/offline intent, not relative group rules. Missing: reference/direction rules, orientation precedence, anchors/preview/markers, per-rule enable, group conflict resolution, independent startup switch and apply-all scope. Removal is immediate (`Apps/OpenDisplay/Sources/SettingsView.swift:210`, `Apps/OpenDisplay/Sources/SettingsView.swift:247`).
- **Implementation notes**: L; public CoreGraphics arrangement transactions and AppKit marker panels suffice for placement/main selection (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider.swift:371`). Keep lifecycle reconnection/rotation SPI separate. Add graph conflict/cycle analysis and explicit coexistence with existing snapshot restoration; preserve debounce, recovery and intentional-offline guards. Backlog SO-08.
- **Acceptance criteria**:
  - Relative positions survive a size change and honor independently chosen anchors; portrait-specific precedence, including disabled-specific masking, is explicit.
  - Apply-all ignores inactive/missing/mirrored participants, resolves priority/opposing pairs deterministically and verifies resulting origins/main status.
  - Disable/removal leaves the current desktop intact; Cancel preserves the rule; live markers never outlive their editor.

### 4. Physical UI scale matching — [UI Scale Matching](https://betterdisplay.pro/guide/interface-reference/settings/groups/group/ui-scale-matching/)

- **BetterDisplay behaviour** (Pro): Settings > Groups > group > UI Scale Matching is initially off and requires active membership, usable physical dimensions and suitable modes. Advanced chooses watched sources and affected targets independently. Compare logical size per physical dimension, choose a nearby existing target mode, retain target aspect ratio and where possible HiDPI, rate and depth. Never change the originating source or a mirror target, and never create a mode. A virtual display's diagonal and optional physical-size override are reported metadata, not a measurement.
- A blank tolerance field means 10%; both dimensions must fit. If no mode qualifies, leave the target alone. Updating a protected resolution is separately permitted by an initially-off toggle; off means skip protected targets, on updates the protected value too. Applied changes remain after disabling matching. Shift bypasses a menu mode change; for delayed slider changes Shift must remain down through application.
- Outside-app mode watching defaults off. Only with it on can connection enforcement be enabled (initially off); normally a newly affected display follows an existing watched member. A dependent, initially-off option permits a newly connected display to lead. Conflicting watched proposals for a target cause that target to be skipped. Preferences act on the next relevant event, with automatic work beginning after startup finishes.
- Watch-all and affect-all default on; automatic inclusion of virtual screens defaults off on each side. Automatic exclusions are separate from explicit lists; explicit lists may include virtuals regardless of automatic switches. Editors include connected/disconnected/remembered members, reveal unselected absent entries on demand, always retain selected absent entries, show empty-state feedback and support Option-identification. Missing targets cannot receive a mode.
- **FreeDisplay today**: ⬜ Missing. Group schema has no scale policy (`Packages/TopologyCore/Sources/TopologyCore/DisplayGroup.swift:14`); available mode selection is local to a display (`Apps/OpenDisplay/Sources/TrayModeCatalog.swift:93`). Physical millimeters are collected for identity (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider.swift:339`) but no matching executor or editor uses them. Snapshot protection is not physical scale matching.
- **Implementation notes**: L. Public CoreGraphics size/mode enumeration and configuration plus pure matching can implement this. Add calibrated/manual physical dimensions and explicit unknown-size state. Batch proposals before writes, preserve transaction rollback, and arbitrate with protection. Creating additional flexible/virtual modes is a separate private-API project, not a requirement of the matcher. Backlog SO-09.
- **Acceptance criteria**:
  - Different-sized screens select different logical resolutions for equal physical UI size; both tolerance axes must pass.
  - Conflicting sources, missing dimensions, no suitable mode, protected targets and mirror targets produce explained skips.
  - Connection dependencies, explicit virtual lists, Shift bypass and protected-value updates survive relaunch without undoing applied modes.

### 5. Application startup, privacy and timing — [Application](https://betterdisplay.pro/guide/interface-reference/settings/application/), [Startup and privacy](https://betterdisplay.pro/guide/interface-reference/settings/application/startup-and-privacy/)

- **BetterDisplay behaviour** (Free; licensing provider permission is business-specific): Application groups startup, updates, notification/Dock and integration settings, links to macOS Shortcuts, and exposes Advanced Settings & Privacy. Login registration reflects macOS after a brief loading state; disabling unregisters it. Users can also manage it in System Settings > General > Login Items. The guide does not specify the initial login preference.
- Automatic Sentry crash reporting defaults on and is saved; disclose that hardware-specific information may be included. Where distributed with licensing controls, a permission switch permits trial, purchase and license management/network access. Turning it off limits access to free features and refreshes state; it does not remotely deactivate a license.
- Optional configuration delay: blank = 0.2 seconds, allowed 0–10. Wake delay: blank = 1.5 seconds, allowed 0–10. Animation duration: 0–2 seconds; zero disables transitions; blank uses the displayed default, whose numeric value is not specified. Blank is not zero. Persist overrides and support returning to automatic/default behavior independently.
- **FreeDisplay today**: ✅ Implemented login registration via `SMAppService.mainApp`, approval-required feedback, errors and refresh on activation (`Apps/OpenDisplay/Sources/LaunchAtLogin.swift:11`, `Apps/OpenDisplay/Sources/LaunchAtLogin.swift:35`, `Apps/OpenDisplay/Sources/LaunchAtLogin.swift:47`), placed in Diagnostics (`Apps/OpenDisplay/Sources/SettingsView.swift:484`). 🟡 Partial application organization: no Application section (`Apps/OpenDisplay/Sources/SettingsView.swift:80`). ⬜ Missing configurable delays/animation and a privacy summary. `Packages/TopologyCore/Sources/TopologyCore/SettingsStore.swift:156` has no such fields; tray timings are fixed (`Apps/OpenDisplay/Sources/MenuBarView.swift:1016`, `Apps/OpenDisplay/Sources/TrayPanelController.swift:255`). No Sentry/crash-reporting integration was found in application/provider/package source; absence of an app crash uploader is not absence of macOS diagnostics. ➖ Licensing-provider permission is not applicable.
- **Implementation notes**: M for settings organization/delay policy, S for a truthful privacy panel. Public ServiceManagement, NSWorkspace wake notifications and SwiftUI animation settings. Retain opt-in privacy posture; there is no need to add telemetry merely for parity. Avoid spreading independent sleeps across services; debounce from a shared configuration-event policy. Backlog SO-10.
- **Acceptance criteria**:
  - Login state refreshes after external System Settings changes and shows approval/failure states distinctly.
  - Blank, zero and out-of-range timing values have different documented results; animation zero/Reduce Motion produces no transition animation.
  - Privacy text describes only actual FreeDisplay data flows and contains no inactive licensing controls.

### 6. App configuration backup, replacement and lifecycle — [Startup and privacy](https://betterdisplay.pro/guide/interface-reference/settings/application/startup-and-privacy/)

- **BetterDisplay behaviour** (Free): Advanced exports stored preferences to a user-selected plist; import selects a plist and replaces stored app preferences. Failures display the error and an acknowledgement. A successful import requests Restart and explains that display IDs may differ between installations, requiring display-settings transfer. This is replacement, not a merge.
- Reset asks for confirmation, restores app defaults and restarts. Cancel changes nothing. Custom display configuration already written to macOS survives the app reset. Reset Warning Dismissals acts immediately, acknowledges completion and preserves unrelated preferences. Restart and Quit from this sheet each confirm; cancellation keeps the app running. These differ from direct application shortcuts described below.
- **FreeDisplay today**: ⬜ Missing user-facing app-settings export/import/reset and warning-dismissal reset. `Packages/TopologyCore/Sources/TopologyCore/SettingsStore.swift:414` supplies atomic JSON load/save only; corrupt/unreadable input silently falls back to defaults (`Packages/TopologyCore/Sources/TopologyCore/SettingsStore.swift:434`). Diagnostics export (`Apps/OpenDisplay/Sources/SettingsView.swift:336`) is not a restorable settings backup. Tray Quit is immediate (`Apps/OpenDisplay/Sources/MenuBarView.swift:1003`), with teardown managed by `Apps/OpenDisplay/Sources/OpenDisplayApp.swift:235`. There is no equivalent Advanced lifecycle sheet.
- **Implementation notes**: M. Use public NSOpenPanel/NSSavePanel and a versioned, validated FreeDisplay archive; JSON is acceptable, BetterDisplay plist compatibility is not required. Include registry/favorites/group references deliberately and reconcile UserDefaults-based tray preferences. Exclude session secrets and recovery ledgers that would replay stale hardware actions on another Mac. Separate app reset from WindowServer configuration changes. Backlog SO-11.
- **Acceptance criteria**:
  - Export/import round-trip documented persistent settings; invalid archives report errors without losing the current configuration.
  - Replacement and restart are explicit; unmatched display identities receive a remapping workflow rather than accidental targeting.
  - Reset/Restart/Quit cancellation is inert; warning reset touches only dismissals; app reset leaves system display configuration intact.

### 7. Update preferences and complete update lifecycle — [Updates](https://betterdisplay.pro/guide/interface-reference/settings/application/updates/)

- **BetterDisplay behaviour** (Free; newer-version license compatibility remains separate): Application > Updates defaults automatic checking on and automatic downloading off. Disable checking to disable the download control while retaining its value. Controls briefly wait for updater preference loading. Application's manual check navigates to About and reports inline; selecting an available result opens the offer. A check initiated in About requests an offer immediately when found. Scheduled discoveries may use menu/Dock indicators and an install notification, subject to permission, or show an offer directly around launch.
- Pre-release and nested internal-pre-release preferences both start off and persist. Internal can contain unfinished changes and not every internal build is automatically offered. Turning a channel off does not downgrade the installed build: an installed test/internal build can continue that channel until superseded by stable. Feed contents, processor architecture and OS range determine applicability.
- Offers show installed/offered versions and optional release notes, with scrolling, links, loading/error feedback. Notes failure is independent of update availability. Notes-bearing offers are resizable with remembered size; no-notes offers are compact. Install begins/resumes the update and may require quitting. Later dismisses without skipping and is hidden if automatic checks are off; closing also dismisses. Skip remembers the version, discards any prepared copy and suppresses ordinary versions at/below it; a major-upgrade skip can exclude that upgrade line. Manual checking clears the skip. An automatic-install checkbox appears only for an installable offer with automatic checks on and edits the same saved preference.
- Informational offers substitute a Learn More link and have no auto-install checkbox. Critical non-major releases omit Later and Skip. Prepared updates can show install-and-relaunch and install-on-quit; downloaded-but-unprepared updates may still show ordinary Install. Dismissal retains a downloaded update for resume. Escape invokes Later when present; Return invokes Install when it has default focus.
- Download progress supports Cancel and displays bytes with or without a known total. Extraction disables cancellation. App ownership/location can trigger administrator authorization; cancel stops that attempt without changing scheduled-check preferences. Ready-to-install may require explicit relaunch; replacement has no enabled action. Delayed termination can close progress and require reopening the offer. Automatic/prepared flows may skip visible intermediate windows. Usually the app reopens without a success alert; installation without reopening may report the new version in a completion alert.
- Distinguish up-to-date, OS-too-old, OS-too-new and checking failure. Outside an inline check, a no-update dialog may identify newest version/OS range and conditionally expose history or information links. Inline errors stay inline; later errors use an alert with description/recovery advice and a cancel-update action. Neither an error nor successful download means installed.
- **FreeDisplay today**: 🟡 Partial infrastructure, intentionally inactive in this fork. `Apps/OpenDisplay/Sources/SoftwareUpdater.swift:45` uses Sparkle's standard driver, applies auto-check/download (`Apps/OpenDisplay/Sources/SoftwareUpdater.swift:72`), mirrors its checkbox (`Apps/OpenDisplay/Sources/SoftwareUpdater.swift:107`), guards downgrade (`Apps/OpenDisplay/Sources/SoftwareUpdater.swift:162`), handles found/skipped/installing events (`Apps/OpenDisplay/Sources/SoftwareUpdater.swift:172`) and gentle reminders (`Apps/OpenDisplay/Sources/SoftwareUpdater.swift:215`). Defaults match (`Packages/TopologyCore/Sources/TopologyCore/SettingsStore.swift:186`). However `Apps/OpenDisplay/Resources/Info.plist:43` marks every build local to avoid replacing the fork with upstream; `Apps/OpenDisplay/Sources/SoftwareUpdater.swift:55` and `Apps/OpenDisplay/Sources/SoftwareUpdater.swift:85` suppress checks and explain source-based updating. No selectable channels, inline cancellation, persistent error/OS-compatibility state, Dock badge or notification plumbing is present. `SoftwareUpdatePhase` has no error/incompatible cases (`Packages/TopologyCore/Sources/TopologyCore/SoftwareUpdate.swift:47`), and completion ignores its error argument (`Apps/OpenDisplay/Sources/SoftwareUpdater.swift:196`). The standard driver is a dependency-backed implementation path, not proof that every described offer variant was exercised.
- **Implementation notes**: M for app status/preferences, L for fork release/signing pipeline. Sparkle is a third-party updater, not private macOS display API. Keep the local-build guard until a FreeDisplay-owned signed feed, identity and signing key are ready. Reuse standard update windows and validate their release-metadata-dependent behavior rather than writing an installer. Backlog SO-14/SO-15/SO-16.
- **Acceptance criteria**:

- **Acceptance criteria**:

### 20. Physical connection, DDC power and virtual-screen shortcuts — [Custom Keyboard Shortcuts](https://betterdisplay.pro/guide/interface-reference/settings/keyboard/shortcuts/)

- **BetterDisplay behaviour** (Pro): Disconnect pointer screen, connect all, disconnect all except main, and toggle built-in need enabled/supported connection management and safety conditions. Manually reconnecting a built-in that was automatically disconnected for an external may suspend auto-disconnection and notify, allowing it to remain on.
- Apple-silicon software disconnection should remove desktop participation and enter standby, but panels may not turn/stay off. Intel software disconnection is not full standby and can behave unexpectedly; physical off/unplug/lid closure while logically disconnected can strand the Mac until restart. Affected M3 built-ins retain the additional permission/safety prerequisite cited by the guide; this page does not define its exact model matrix.
- DDC screen-on/screen-off use the screen/backlight controller; display-off is a distinct monitor power-off command. All target pointer screen and require the matching controller. Power-off may need physical buttons to recover; it is not software dimming or logical disconnection.
- Virtual actions: disconnect-if-unassociated and reconnect act on the connected pointer virtual screen; reconnect destroys/reconnects that connection. Bulk disconnect/connect of disassociated virtuals also permits definitions whose association enforcement is disabled. Reconnect-all-connected cycles every connected virtual, including associated ones. Preserve definitions across disconnect; association rules decide eligibility.
- **FreeDisplay today**: 🟡 Partial underlying lifecycle, ⬜ Missing all named bindings except reconnect-all. `Packages/TopologyCore/Sources/TopologyCore/KeyboardShortcutRegistry.swift:6` only exposes recovery; lifecycle uses private SkyLight (`Providers/ExperimentalLifecycleProvider/Sources/ExperimentalLifecycleProvider.swift:10`) with shared safety/recovery. It lacks persistent disconnected definitions, associations and bulk/reconnect shortcut semantics. DDC and connection operations are not interchangeable. Do not infer full standby from a successful logical disconnect.
- **Implementation notes**: L for virtual-definition/association lifecycle; M for routing existing connection/power commands. Private SkyLight, IOAVService and CGVirtualDisplay require feature probes and isolation; no general public external-monitor disconnect API is established by this code. Retain last-active-display checks, watchdog/recovery and offline intent. Backlog SO-33.
- **Acceptance criteria**:
  - All actions resolve the intended pointer/set target and cannot strand the last usable display; explicit built-in reconnect suppresses auto-off for the documented interval/policy.
  - Logical disconnect, backlight off and power-off report distinct outcomes and recovery instructions; physical standby remains separately verified.
  - Virtual bulk operations honor association enforcement, preserve saved definitions and leave unavailable/safe-mode paths inert.

### 21. Stream/PIP control, crop and input-source shortcut slots — [Custom Keyboard Shortcuts](https://betterdisplay.pro/guide/interface-reference/settings/keyboard/shortcuts/)

- **BetterDisplay behaviour** (Pro): Full-screen stop-all also stops PIP; full-screen hide-all toggles visibility only of full-screen streams. Pause-all covers both types: per source, derive the newly toggled state from its first active stream and apply that state to the source's active streams. Repeated pause/warp rows share bindings.
- PIP start/stop first uses its remembered display/window, not the pointer. Without remembered selection, prefer an active PIP on a virtual source, then non-main, then any; if starting a new one, prefer virtual display, non-main display, then first available. Cursor warp maps the source pointer position into a stream window, trying that source's PIP before full-screen targets and requiring a valid coordinate mapping.
- Full-screen and PIP each have independent crop-toggle plus increase/decrease width, height, origin-X and origin-Y bindings. Select an eligible active source under the pointer, else virtual, else non-main, else any active source of the right stream kind. Toggle assigns one crop-enabled state to that source's relevant streams. Geometry changes require crop already on and apply to all applicable cropped streams for that source. Hold accelerates changes; dimensions stay 1–100% and origin/size remain inside source bounds. These are not brightness percentage steps.

Offer displays when a controller supplies input choices; choose display then input then binding, without switching during setup. Execution can remove the Mac's video signal. Retain remembered missing target/input labels and explicitly show unavailable choices; a missing explicit target never redirects. Clear input to remove the operation. - **FreeDisplay today**: 🟡 Partial PIP/input primitives, ⬜ Missing stream shortcut family. `Apps/OpenDisplay/Sources/CapturePanel.swift:185` supports one settings-owned SDR PIP with source picker, start/stop, flip/rotation, symmetric crop 0–0.4 and LUT; it stops on leaving the pane (`Apps/OpenDisplay/Sources/CapturePanel.swift:220`). Offline execution is guarded in `Apps/OpenDisplay/Sources/AppModel.swift:1936` (`switchInputByHotkey`); this is useful existing behavior.
- **Implementation notes**: L for app-scoped streams and mapping, M for input UX. Public ScreenCaptureKit/AppKit/CoreImage cover capture, crop and PIP; Screen Recording authorization, protected content, Spaces and coordinate transforms remain constraints. Input DDC is private IOAVService and hardware-specific. Keep imported LUT/capture state separate from global shortcut persistence. Backlog SO-34/SO-36.
- **Acceptance criteria**:
  - All stream targeting fallbacks are deterministic, remembered PIP wins, and stop/pause scope includes exactly the documented types.
  - Crop controls affect the right source/type, clamp dimensions/origins, accelerate when held and do nothing before crop enable; cursor mapping works under scaling/rotation or declines safely.
  - Every input slot survives absent hardware, configuration causes no input switch, clearing display preserves input, and unavailable explicit targets never redirect.
