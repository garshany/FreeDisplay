## Topics

Effort: **S** = focused UI/policy work; **M** = a component plus persistence and failure handling; **L** = a new subsystem or substantial hardware validation. These are relative estimates, not elapsed-time promises. Public API availability does not establish panel support. Private/API-risk estimates describe the proposed implementation, not an assertion about BetterDisplay internals.

### 1. Settings shell and display selection — https://betterdisplay.pro/guide/interface-reference/settings/ ; https://betterdisplay.pro/guide/interface-reference/settings/displays/

- **BetterDisplay behaviour (Free; Pro labels identify gated underlying features):** Open Settings from the app menu or Option-click the menu-bar icon. Sidebar order is Displays, Groups, Application, Menu, Keyboard, Pro, About. Displays/Groups have overview and item selectors; selecting an item edits it without connecting a display or enabling a group. Remembered offline devices can remain editable, but live operations require connection. Virtual definitions have their own settings and, when linked, ordinary desktop settings.
  - Keyboard indicates missing Accessibility permission; Pro indicates trial/license problems; About indicates updates. Persist the help-text visibility preference, selected pane and window position/size. Closing Settings keeps the utility running. A sidebar menu button toggles the app menu; Guide opens the website. A bottom question-mark button opens the reference for the selected overview/display/virtual screen/group.
  - Language choices are sorted by displayed name; hover distinguishes current language from a choice requiring restart. Selecting the current choice closes the picker; another saves, relaunches and reopens Settings. Globe/close dismisses without changing it.
  - Controls explain prerequisites and Experimental/Pro state. Expanders and resizable sheets organize settings; many sheet sizes persist. Done closes, not universally cancels or applies. Blank optional numeric fields mean their documented default/automatic value, not necessarily zero.
  - Shared SF Symbol picker: search names/related terms, scroll grid, select immediately, show selected name, Remove only when a custom symbol exists, Done closes. Symbols vary with installed macOS.
  - Pending model overrides show red Apply/Undo: apply all pending override edits or discard those edits, without resetting ordinary preferences. Installation may need helper/admin authorization and reports errors; Shift requests the administrator route. An orange post-install notice requires activation/reboot. Apple-silicon activation appears for eligible connected externals; its confirmation warns about 2–4 seconds of blanking, temporary loss of interaction, possible sleep, and built-in displays still needing reboot. Cancel does not activate; Dismiss hides the notice without completing activation.
- **FreeDisplay today:** 🟡 Partial. Option-click Settings and an independently retained resizable window exist in `Apps/OpenDisplay/Sources/OpenDisplayApp.swift:141` and `:172`. The window is centered on the pointer's screen each time, not restored to its last position. `Apps/OpenDisplay/Sources/SettingsView.swift:18` starts with Displays; `:81` defines nine different sections. `:116` selects live observations, without a full remembered-device settings browser. Language persistence/relaunch exists in `Apps/OpenDisplay/Sources/Localization.swift:16` and `:41` (System/English/Russian); full guide-language selector semantics are absent. Missing shared help preference, contextual guide links, symbol picker, sidebar conditions and durable pane/sheet geometry. Model Apply/Undo/activation is absent: the advanced pane explicitly exports only (`Apps/OpenDisplay/Sources/AdvancedDisplayToolsView.swift:37`). ➖ Pro licensing/business UI is not applicable.
- **Implementation notes:** S/M for SwiftUI navigation, AppKit frame autosave, UserDefaults and links; M for reusable editors. Separate draft state from committed preferences. Model installation/activation is L and privileged/private-risk work described in topic 25; do not imply ordinary SwiftUI persistence installs overrides.
- **Acceptance criteria:**
  - Option-click and the menu entry open the same Settings window; closing it leaves the tray available. Relaunch restores pane/window geometry.
  - Selecting an offline device or disabled group performs no display mutation; unavailable controls explain their prerequisites.
  - Language no-op/cancel does not relaunch; a changed language restores Settings. Clear/default/Done/Cancel semantics are explicit in each editor.
  - Pending override notices survive a dismissed activation reminder and never claim activation merely because installation succeeded.

### 2. Overview, global limits, identification and reset — https://betterdisplay.pro/guide/interface-reference/settings/displays/overview/

- **BetterDisplay behaviour (mostly Free):** Settings → Displays → Overview separates physical displays and saved virtual definitions. Connected icons are bright; app-disconnected entries have a power badge; remembered absences have an unavailable badge; associated virtual definitions are labeled. The offline-display inclusion preference defaults off. No detected display produces an error notice. Row click opens settings; Option-click identifies the linked visible desktop, and cannot identify an absent virtual desktop. Creation and advanced virtual-management buttons are present.
  - Advanced Display Settings: disabling Night Shift/True Tone during app-initiated nonvirtual HDR transitions defaults off (**Pro**). Restore only effects this operation disabled when returning to SDR. Unlocking Apple display profile management defaults off (Free), reconfigures immediately and warns that presets work best with factory profiles.
  - Switching a separate full-screen stream target to its default mode defaults off (**Pro**): save its current mode, choose default on stream start, restore on stop. “Native” wording does not guarantee native pixels. DisplayLink discovery defaults on (**Pro**), uses installed current support and can be disabled for compatibility. Intel quick mode changes skip fades, default on; ➖ Intel-only for this Apple-silicon product.
  - Both resolution-limit extensions default off. Below-720p permits smaller slider/virtual modes, immediately refreshes mode choices and warns about UI fitting. If virtual desktops are connected, offer reconnect all currently connected screens or defer. Over-8K expands flexible/virtual generation toward 16K×16K (8K×8K HiDPI); actual generated maximum is 15,360 on either axis. Hardware/macOS limits and instability remain. Flexible scaling must be reapplied; generated-mode virtual screens trigger the prompt, whose acceptance still cycles all connected virtual screens. Decline saves the preference for later.
  - Default identification applies only to newly discovered records and starts Automatic by type. Alternatives: system UUID; vendor/model/serial; vendor/model/name; vendor/model; vendor/serial; name only; basic plus product name/alphanumeric serial/manufacture date; that extended set plus port (Apple silicon) or location; full EDID with UUID fallback when missing. Broader matching can merge similar devices; port/location matching binds identity to cabling. Existing devices have their own setting.
  - Automatic forgetting defaults on; known-display minimum retention is 90 days, editable immediately with blank restoring defaults. **Documented defect:** the unknown-display field displays a default of 1 day but is interpreted as seconds, with removal evaluated on display-list updates. Turning forgetting off avoids that defect; do not copy its units bug.
  - System reset confirmation offers cancel, reset display system state, or reset plus NVRAM. It removes macOS configuration, generated factory profiles and installed overrides, forgets app display records, and requests reboot. NVRAM also affects startup/boot settings. Uses helper/admin authorization, with Shift selecting administrator prompting and cancellation aborting.
  - Separate Forget All confirmation removes app records, their virtual associations and saved vendor/model overrides; redetects/reconfigures. It does not delete virtual definitions or perform the system-reset/reboot. Matching models can share affected overrides.
- **FreeDisplay today:** 🟡 Partial. Live selector and empty state: `Apps/OpenDisplay/Sources/SettingsView.swift:116`; tray Option-identify: `Apps/OpenDisplay/Sources/MenuBarView.swift:206`; flash implementation: `Apps/OpenDisplay/Sources/TrayPanelController.swift:430`. Persistent records and UUID/fingerprint matching exist in `Packages/TopologyCore/Sources/TopologyCore/DisplayRegistry.swift:67`, but there is no configurable match-method/retention/forget editor. Its `:148` matches serial without vendor/model, and `:162` takes the highest score without a tie check: distinct devices can inherit one record. ICC operations exist (`Apps/OpenDisplay/Sources/ColorProfileService.swift:19`), not HDR effect-state ownership or the Apple-profile unlock preference. Virtual bounds are fixed (`Packages/DisplayDomain/Sources/DisplayDomain/VirtualDisplayDefinition.swift:18`). No shared generated-mode limits, stream-target mode restoration, DisplayLink discovery or scoped reset workflows were found in Settings/AppModel/settings schema. System reset must not be confused with monitor factory reset at `Apps/OpenDisplay/Sources/DisplayDetailView.swift:441`.
- **Implementation notes:** M for a persistent inventory, identity strategies, uniqueness checks, explicit retention durations and app-record deletion. Public CoreGraphics/ColorSync for available information; port/extended identity may need IOKit properties with uncertain availability. HDR system-effect toggles require separate platform/SPI investigation. L/high risk for system reset/helper; NVRAM cleanup is niche and should remain separate. Keep virtual, app-record, model-override and macOS-reset scopes distinct.
- **Acceptance criteria:**
  - Two identical monitors and two different models with the same numeric serial never silently share settings; ambiguous matches require resolution.
  - Known/offline/soft-disconnected/virtual states remain distinct; retention uses actual elapsed days and preserves associations until intentional deletion.
  - Limit changes either reconnect the documented set or remain pending; never claim the larger mode is supported before enumeration/connection.
  - HDR exit restores only app-owned effect changes; each reset preview lists its exact scope and cancel leaves all scopes unchanged.

### 3. Virtual-screen creation — https://betterdisplay.pro/guide/interface-reference/settings/displays/overview/create-virtual-screen/

- **BetterDisplay behaviour:** Available from Overview and the app menu's display/virtual-screen tools. **Free** preset creation saves a disconnected definition and selects it after the list refreshes. Presets specify shape and spacing rather than a single pixel mode. Default is 16:9. Standard ratios: 16:9, 16:10, 4:3, 17:9; ultrawide: 21.3:9, 21.5:9, 24:10, 32:10, 32:9; other: 1:1, 3:2, 5:4; iPad: 4:3, 15.2:10 Mini 2021, 14.4:10 Air 2020, 14.3:10 Pro 11-inch. GPU/macOS still decide mode usability.
  - **Pro** matching requires a connected target with valid native dimensions; derives its ratio, including supported notch/iPad Mini corrections, and generates a target-based name. Association defaults on, so creation may immediately connect; off saves a matching definition without that rule.
  - With association, full-screen streaming connects source, enables later automatic streaming, attempts a nearby HiDPI mode matching target desktop dimensions, and transfers main-display role from target to virtual source if appropriate. Mirroring is a separate initially-off option shown when streaming is off; enabling streaming clears mirroring. Stream rotation offers 0°, 90° (Sidecar port down) or 270° (port up), swaps source dimensions for portrait and rotates presentation independently of target hardware rotation.
  - Streaming needs Screen Recording permission. Missing access shows a warning and disables rotation; reopen creation after granting permission to refresh state. A stream attempt without permission reports failure. **Documented edge:** hiding association options does not clear a previously selected streaming option or its permission check; turn streaming off first. Prefer explicit state normalization in FreeDisplay.
  - **Pro** custom ratio components are proportions, default blank values 16×9, constrained 1–16,384; generated spacing is chosen automatically. Cancel creates nothing. Later custom resolution lists can contain mixed ratios. If matching/connection/streaming fails after saving, a definition may remain: inspect it rather than creating duplicates. The UI recommends flexible scaling for suitable physical displays and virtual presentation for cases such as portrait Sidecar.
- **FreeDisplay today:** 🟡 Partial. `Apps/OpenDisplay/Sources/VirtualDisplaysSettingsView.swift:8` offers name, pixel width/height, 30/60/120 Hz, HiDPI (default off), explicit experimental consent and immediate creation. `Providers/VirtualDisplayProvider/Sources/VirtualDisplayProvider.swift:45` enforces safe-mode/runtime availability, a recovery-surface heuristic, four-screen limit and observed pixel verification. No saved-disconnected definition, preset/ratio generation, matching, association, automatic main-role/presentation setup or creation wizard. Capture is separate (`Apps/OpenDisplay/Sources/CapturePanel.swift:64`).
- **Implementation notes:** L. Persist definitions independently of private `CGVirtualDisplay` handles, then implement preset/matching generation and an explicit connection action. Public CoreGraphics supplies target geometry; ScreenCaptureKit supplies capture, with permission handling. Treat definition-save, connection and presentation as separate results; rollback main role/mode if presentation fails. Preset UI is public, but creation backend remains private.
- **Acceptance criteria:**
  - Preset creation saves without adding a desktop; Connect creates it, and failed connection retains one editable definition.
  - Each listed shape generates proportional modes; invalid/missing targets fail clearly. 16×9 means ratio, not pixels.
  - Streaming/mirroring choices are mutually consistent; denial cannot leave a hidden streaming request. Portrait presentation and main-role restoration are verified separately.

### 4. Virtual-screen bulk lifecycle and workarounds — https://betterdisplay.pro/guide/interface-reference/settings/displays/overview/advanced-virtual-screen-settings/

- **BetterDisplay behaviour (Free settings/actions; associations retain their own Pro requirement):** Advanced Virtual Screen Settings saves immediately. Normal startup restores saved connected screens; Safe Mode suppresses restoration. Apple-silicon layout restoration defaults on: preserve existing positions/modes during first connection, aspect flips and configured virtual mirroring; place a new desktop beside the layout.
  - Defaults off: Apple-silicon mirrored-sleep workaround creates a temporary virtual display during sleep; reconnect on wake; reconnect remaining connected screens after removing one; disconnect on lock/screensaver and restore only previously connected screens on return. These can interrupt other desktops and are optional compatibility workarounds.
  - Connect All connects disconnected definitions; Disconnect All retains definitions; Reconnect All cycles only connected definitions. Disable each action if there is nothing eligible. First two skip association-managed connections and report skips; reconnect includes connected association-managed screens.
  - Discard All is disabled with no definitions and first asks Cancel/Discard. If factory profiles exist, a second choice skips profile removal or requests authorized removal. Skip still deletes definitions; no profile prompt if none exist. Disconnect instead when retaining macOS configuration matters.
  - Disassociate All is enabled only with relationships, asks confirmation, removes every relationship, and preserves definitions, modes and current connections.
- **FreeDisplay today:** ⬜ Missing bulk/persistent lifecycle. Existing session create/destroy at `Providers/VirtualDisplayProvider/Sources/VirtualDisplayProvider.swift:25` and `:81` deliberately has no startup restore; endpoints live in memory. `Apps/OpenDisplay/Sources/VirtualDisplaysSettingsView.swift:54` only lists/removes endpoints. There are no virtual sleep/lock policies, bulk buttons, factory-profile cleanup or associations. Existing physical wake/layout machinery is separate (`Apps/OpenDisplay/Sources/AppModel.swift:3727`).
- **Implementation notes:** L, private creation API plus public lifecycle notifications and arrangement snapshots. Track exactly which screens each temporary lock/sleep operation owns. Default to saved definitions without automatic restoration until its recovery path is validated. Profile cleanup requires a scoped privileged path; never delete unrelated profiles.
- **Acceptance criteria:**
  - Bulk connect/disconnect reports association skips; reconnect never connects an initially disconnected definition.
  - Lock restoration reconnects only the prior connected set; Safe Mode creates no automatic desktops.
  - Disassociate leaves desktops intact. Both discard prompts clearly distinguish definition deletion from optional profile cleanup; failure reports partial completion.

### 5. Physical connections and recovery policy — https://betterdisplay.pro/guide/interface-reference/settings/displays/overview/connections/

- **BetterDisplay behaviour (Pro, with recovery exceptions):** Global connection management defaults on; off disables dependent settings and reconfigures. Soft disconnect removes layout participation; standby is connection-dependent on Apple silicon, and not complete sleep on Intel. Non-native removal need not end the remote session or power off a panel.
  - **Documented prompt mismatch:** an alert described as disable-time recovery currently appears on enabling management with disconnected displays. Reconnect attempts all; decline leaves them off. Explicitly reconnect before disabling; do not reproduce this mismatch. Menu power/replug/lid close-open are possible recovery routes, not guarantees. Intel unplug/power-off/lid-close after soft disconnection can require restart.
  - Default safety requires another suitable screen. Allow-all-disconnect defaults off; enabling disables none-left automatic recovery. App virtual and most system virtual displays do not count; recognized DisplayLink can.
  - Re-disconnect app-off screens after wake defaults off, waits for wake delay, and exempts the new main screen. Intel full dim-on-disconnect defaults on and remembers prior brightness. Retain app-disconnected Sidecar defaults on, without discovering arbitrary prior sessions. Non-native external disconnection defaults off.
  - Built-in settings appear on Apple silicon/iMac. iMac disconnection override and affected non-iMac M3-display-GPU override default off; recovery warnings explain cable/lid limitations or possible reboot. Apple-silicon automatic built-in disconnect defaults off, needs suitable nonvirtual external presence and its per-display exception off; iMac/M3 safety override is prerequisite. Safe Mode suppresses it. Manual built-in reconnect suspends the rule; changing preference, manually disconnecting again or relaunch can restore it. An already-enabled rule remains switchable off without Pro.
  - Auto-connect on startup, normal quit, and no suitable screens left all default on. Forced termination cannot perform quit cleanup. Generic temporary screens and ordinary virtual desktops do not count for none-left recovery. Preserve soft-disconnected state across launches defaults off; offered when startup/quit reconnection are both off or preservation is already on. It remembers attached-but-off identity, not physical presence. Closed lid and exclusive system-virtual sessions can block reconnect. All preferences persist immediately.
- **FreeDisplay today:** 🟡 Partial. Logical disconnect, offline ledger and reconnect verification exist (`Apps/OpenDisplay/Sources/AppModel.swift:3297`, `:3345`); last-surface preflight is in `Packages/TopologyCore/Sources/TopologyCore/SafetyEngine.swift:61`. Built-in automation is an arrival-edge policy, not all of the guide rules (`Packages/TopologyCore/Sources/TopologyCore/AutoDisconnectBuiltInPolicy.swift:26`). Wake reassertion is automatic, without the guide's default-off setting (`Apps/OpenDisplay/Sources/AppModel.swift:3787`). Missing global enable, per-display exception/aggressive policy, model-specific M3/iMac restrictions, Sidecar/DisplayLink integration and configurable startup/quit preservation.
  - **Existing defect:** normal-quit cleanup ignores reconnect failures, then erases the offline ledger (`Apps/OpenDisplay/Sources/AppModel.swift:4100`). It can lose the recovery intent while a screen remains disconnected.
  - **Review risk:** safe-surface selection filters activity/mirroring/overlay but not virtual class (`Packages/TopologyCore/Sources/TopologyCore/SafetyEngine.swift:43`); classification recognizes synthetic placeholders rather than all virtual transports (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider.swift:298`). App-created/third-party virtual screens must not be assumed physically visible. The separate virtual-session guard excludes its own vendor when creating, but accepts any other nonzero external vendor as a heuristic (`Packages/DisplayDomain/Sources/DisplayDomain/VirtualDisplaySafetyPolicy.swift:16`); it is not shared with lifecycle preflight.
- **Implementation notes:** L; preserve the existing coordinator and checkpoint/recovery path. Current soft-disconnect backend uses private CGS/SkyLight (`Providers/ExperimentalLifecycleProvider/Sources/ExperimentalLifecycleProvider.swift:10`). Introduce a shared physically-usable-surface predicate with virtual provenance and model-specific risk classification. Public notifications support policy timing, not disconnect itself. Never remove recovery state on an unverified reconnect.
- **Acceptance criteria:**
  - Built-in + virtual-only configurations cannot lose their final physically usable display; verify both HiDPI and ordinary virtual modes and unknown transports.
  - Failed quit reconnect keeps a recoverable ledger; next launch retries and reports failures. Closed-lid recovery does not fight lid state.
  - Each policy has the documented default, trigger and precedence; manual reconnect suspension and per-display exclusions work. Disconnect never claims standby without evidence.

### 6. Shared custom-control definitions — https://betterdisplay.pro/guide/interface-reference/settings/displays/overview/custom-controls/

- **BetterDisplay behaviour:** Overview → Custom Controls manages stable definitions; DDC/integration editors can open it and retain a return path. A definition alone sends nothing. **Pro** add/edit; inspection/deletion remain available without Pro.
  - Add chooses range (default), on/off or command; requires nonempty name. Additional settings accept an SF Symbol or picker, with kind-specific fallback for an unavailable symbol. CLI designation is generated from name with numeric collision suffix, or explicitly supplied; collisions with custom/predefined designations disable creation. Range/toggle synchronization eligibility defaults on; commands omit that switch. Eligibility does not establish group membership or synchronization. Add inserts first; Cancel abandons.
  - Rows show predefined/custom type, kind, sync eligibility and stable designation. Edit permits name/icon only; Done saves, Cancel restores; empty name blocks save. Kind/designation/sync eligibility are immutable there. Option-opening includes predefined read-only entries without edit/delete.
  - Return-to-DDC/integration requires the source display and feature still available, otherwise Done. Assign a definition separately per display. Delete unused definition immediately; if assigned to displays/groups, confirm cascading deletion of implementations/sync references. Rename preserves identity; delete/recreate does not.
- **FreeDisplay today:** ⬜ Missing. Hardware control kinds are hard-coded (`Apps/OpenDisplay/Sources/AppModel.swift:16`); saved group controls are limited to existing group properties (`Packages/TopologyCore/Sources/TopologyCore/SettingsStore.swift:154` and `Apps/OpenDisplay/Sources/AppModel.swift:2956`). Raw VCP support (`Providers/ExperimentalLifecycleProvider/Sources/DDCControl.swift:199`) is not a reusable named-control registry or editor.
- **Implementation notes:** M for Codable IDs, validation, symbol selection and reference integrity; L including generic dispatch/group synchronization. Use separate stable internal ID and CLI designation, normalized uniqueness, typed value domains and explicit assignment records. UI/persistence public; each assigned transport retains its own API risk.
- **Acceptance criteria:**
  - Duplicate/reserved identifiers are rejected; automatic suffixes are deterministic. Rename preserves assignments.
  - Creating a definition performs no I/O. Deleting an in-use control previews and removes every affected assignment only after confirmation.
  - Commands do not acquire ranged synchronization semantics; loss of source display changes the return button safely.

### 7. Custom LUT library and color interpretation — https://betterdisplay.pro/guide/interface-reference/settings/displays/overview/custom-lut-filters/

- **BetterDisplay behaviour:** Overview manager or image/filter-menu Manage opens reusable filters. **Pro** import/add/edit/replace/apply; existing originals can be exported/deleted without Pro. Import stages one UTF-8 3D CUBE, not an immediate color change. Show original filename/dimension; derive unique name from title/filename with suffix. Name comparison trims ends and ignores case/accents. Invalid/duplicate names disable Add; Cancel discards pending import. Store compressed original source independently of its original location.
  - Accept dimensions 2–128 and source ≤256 MiB; reject 1D or mixed LUTs, malformed values/counts and invalid input ranges (each max must exceed min). Explain the import error. Larger grids increase processing/storage, not image resolution.
  - New SDR: HDR off, sRGB, reference white 100 nits; choices sRGB/Rec.709/Display P3. New HDR switches to fixed Rec.2100 PQ, white 203 nits, peak 1000; turning HDR off resets sRGB/100. White must be positive finite; peak finite and greater than white. Placeholder text is not valid input. These are authored assumptions, not brightness gain/measurement; HDR is experimental and requires stable calibration/preset/brightness.
  - Existing entries show range, space, white, optional peak, filename and size. Edit/Upload stages changes; Done updates all uses, Cancel restores all staged fields/source. Replacement preserves identity, assignments and content range. Existing-filter HDR toggling changes space but preserves white; adds 1000 peak only if absent. Export writes the exact stored original with its original filename, without app interpretation metadata; decoding/write errors are shown.
  - Targets independently enable a shared filter: whole display, PIP, filter window, stream. Import alone does nothing. Delete always confirms and counts enabled display/stream assignments, including remembered configurations; removal disables those uses. Apple-silicon stream filtering supports EDR; Intel UI fields do not imply HDR output.
- **FreeDisplay today:** 🟡 Partial. One session LUT can be loaded/reset for SDR capture (`Apps/OpenDisplay/Sources/CapturePanel.swift:168`, `:208`), applied with CIColorCube (`Providers/CaptureProvider/Sources/CaptureImageTransform.swift:22`). Parser limits are 16,000,000 bytes, dimensions 2–64, finite 0–1 samples and standard 0–1 domain (`Providers/CaptureProvider/Sources/CubeLUT.swift:14`). No library, stable assignments, naming, compressed-source export, replacement staging, authored signal-space/white/peak metadata, whole-desktop LUT or HDR pipeline. ### 25. Model overrides, flexible scaling and activation — https://betterdisplay.pro/guide/interface-reference/settings/displays/display/system-configuration/

### 26. EDID retrieval, storage, temporary application and writing — https://betterdisplay.pro/guide/interface-reference/settings/displays/display/edid/

- **BetterDisplay behaviour:** Framebuffer communication service required. Retrieve opens reader; Apple silicon offers custom data except built-in Apple displays; Intel offers device-writing entry, plus its separate model-override loader. **Free** retrieval/export and stored-byte management; **Pro** Apple-silicon apply/reset/auto-apply/continuity/quit cleanup, device memory writing/timing, and Intel model override.
  - Read method OS-managed (recommended, may contain system modifications) or direct I2C. Direct length blank/zero automatic, explicit bounded 1–4096 bytes. Distinguish not-yet-read, failed and acquired bytes. Export enabled after successful read while connected, suggested display-based binary filename, result alert/OK. Acquisition is not validity proof.
  - Interpret version/name/vendor/model/numeric+text serial/manufacture week/year, else show invalid/uninterpretable warning. Selectable representations: Base64, hex numbers, C array, hex-editor blocks, length only. Representation preference global; method/length per display.
  - Import binary or paste Base64 ignoring whitespace; invalid/noncanonical Base64 alerts. Store successful decoded bytes even if EDID interpretation fails, with warning. No field-level EDID editor. Export stored binary; Delete immediately removes saved bytes, both disabled when empty. Errors alert. Removing saved data does not reset active override or undo device writing. Intel override loader instead marks model draft pending and offers neither direct apply nor memory write there.
  - Apple-silicon Apply Custom Now and Reset Factory each confirm/cancel and need connected display. Can flicker/change mode/change identity; replug may recover temporary override, not memory modification. App-menu direct actions omit these Settings confirmations. Automatic detection application off, requires data; disable before factory reset (reset disabled while auto on). Safe Mode suppresses auto-apply.
  - Additional options both on: preserve old/new identity continuity within app session; restore factory EDID during normal quit. Force quit cannot guarantee cleanup; without restoration next launch may see new identity.
  - Physical EDID write can permanently disable display/adapter. Requires connected service, loaded ≤256 bytes and a sheet-local risk unlock, then a second destructive confirmation. Most monitors restrict writes; service mode/emulators differ. Successful send requests reconnect/verify; failure warns possible corruption. Replug does not undo changed memory.
  - Unsaved sheet-specific write settings: chunk 16 bytes, command gap 10 ms, four retries, extra failure wait 20 ms. Suggested chunks 16/8/4/2/1; data must be larger than and divisible by chunk. Delays min 1 ms, retries min zero. These settings do not themselves write.
- **FreeDisplay today:** 🟡 Read/import/export foundation; ⬜ reader UI/formats/custom persistence/application/write. CLI source can read/decode/export current EDID (`Tools/opendisplay/Sources/main.swift:822`; inspected only, not executed). `Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider/EDIDReader.swift:13` uses public IORegistry reads; `Packages/TopologyCore/Sources/TopologyCore/DisplayConfigurationTools.swift:28` strictly validates header/count/checksums/manufacturer, 128–32768 bytes. GUI imports into temporary state and exports an override plist, not binary source (`Apps/OpenDisplay/Sources/AdvancedDisplayToolsView.swift:64`, `:94`). No direct-I2C reader length controls, Base64/hex viewers, saved custom data, apply/unapply/auto-EDID, continuity or physical EEPROM writer.
  - **Existing defect:** live reader returns first product-code match, then built-in/vendor/tree-order fallback (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider/EDIDReader.swift:17`). Same-model monitors or unmatched products can yield another physical device's EDID. A unique CLI selector does not make that downstream association unique.
- **Implementation notes:** M for reliable public IORegistry association, read-only UI, formats and exact-source export; L/high private risk for IOAVService direct I2C/temporary framebuffer EDID. Preserve original blob, parsed validity and target-association confidence separately. Memory writing is niche/P3 and should not share an Apply action with temporary OS overrides; recovery may be impossible. No device writing was performed for this report.
- **Acceptance criteria:**
  - Identical-model monitors with different serials return the correct bytes; ambiguous/unmatched IORegistry data returns uncertainty instead of first candidate.
  - Binary/Base64 export round-trips exactly; acquired-but-invalid bytes stay inspectable without being labeled valid. Clearing storage never claims to unapply.
  - Auto application is suppressed in Safe Mode; factory reset disabled while auto is active; identity/quit ownership survives failure without erasing recovery data.
  - If physical writing is ever shipped, size/chunk rules and two-stage consent are enforced per sheet, and “sent” never becomes “verified” until a separate read/reconnect check.

### 27. Virtual definition, identity and mode generation — https://betterdisplay.pro/guide/interface-reference/settings/displays/virtual-screen/

- **BetterDisplay behaviour:** Definition settings create available modes; choose current mode separately. **Free** connect/disconnect/identify/info/discard and menu visibility/icon/order/local over-8K preference. **Pro** custom name/serial/vendor/model, aspect/rotation/custom list, HDR/HDR-only/rates, spacing/bounds/HiDPI/diagonal and individual associations.

Name blank restores generated ratio-based name. Identify disabled offline; information available if linked current/remembered display exists, disabled only without linked record. Creation-affecting edits while connected show Reconnect/Dismiss: reconnect applies via cycle, dismiss saves for next connection. Presentation-only edits apply immediately.

Empty/zero flagged; editor caps dimensions at 16384; backend removes nonpositive/out-of-range and duplicates. Needs at least one viable mode. **Edge:** empty list falls back to generated modes, nonempty entirely invalid list may fail connection; accepted row does not prove OS acceptance.

### 28. Virtual associations and presentation policies — https://betterdisplay.pro/guide/interface-reference/settings/displays/virtual-screen/associated-displays/

- **BetterDisplay behaviour:** Associations store remembered display identity/fallback name, not current connectivity. Exclude BetterDisplay virtual definitions from choices.   - Association Settings: ordinary auto-connect on → with associations, connect if any connected, disconnect if none; no associations means no rule. Inverse all-offline auto-connect off → connect only if all absent. Enabling inverse disables ordinary connect, mirroring, stream and orientation following; enabling ordinary disables inverse. Either enforced rule blocks manual and bulk connect/disconnect, but connected screens can still reconnect. Safe Mode suppresses automatic changes.
  - Enforced virtual-source mirroring off, disables inverse/stream when enabled. Automatic full-screen stream off, disables inverse/mirror; requires permission and connected source, enabling alone guarantees neither. Orientation following off, disables inverse; toggles virtual shape landscape/portrait, square unchanged. Needed shape change cycles a connected source and attempts PIP restart; manual rotated orientation disabled when following with associations.
  - Multiple associations use “any connected” for connection policy but a single presentation/orientation target, without priority selector or stable-order guarantee. **Documented defect:** an unavailable associated entry can block mirroring to another live candidate. Use one association for reliable target or explicitly configure presentation; FreeDisplay should implement deterministic eligible-target selection.
  - Adding relationships/enabling policy can prompt Connect or Disable Auto-Connect, or Disconnect or Disable Auto-Connect when current state disagrees. Disable clears both connection rules but preserves associations/other behaviours. Later reevaluation can reassert active rule; current-state confirmation is not permanent manual override. - **FreeDisplay today:** ⬜ Missing. - **Implementation notes:** L, public policy engine/storage/CoreGraphics mirroring plus private virtual lifecycle; ScreenCaptureKit/AppKit for full-screen presentation. Choose one deterministic eligible target or expose explicit priority, separate from any-present connection evaluation. Prevent policy cycles and capture recursion; update association references transactionally during record transfer/forget.
- **Acceptance criteria:**
  - Association survives absence with readable name; toggling and identification do not accidentally change each other.
  - Ordinary/inverse connection modes are mutually exclusive, Safe Mode suppresses changes, and manual conflicts explain how to disable policy.
  - Multiple associated screens choose a deterministic connected target; an offline candidate cannot block live presentation. Removing all relationships leaves the desktop connected as-is.
  - Orientation changes preserve modes/layout, attempt PIP restoration and report failures. Missing permission prevents streaming without claiming connection/presentation success.
