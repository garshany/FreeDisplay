## Topics

### 1. Integration entry points, access settings, and security — https://betterdisplay.pro/guide/integration/ · https://betterdisplay.pro/guide/integration/cli-reference/

- **BetterDisplay behaviour** (Free transport; underlying feature tier applies): Settings → Application → Integration enables CLI and notification access by default; custom-URL and HTTP access default off. Integration Settings contains an optional security token and HTTP listening port; blank port means 55777. HTTP readiness is shown after enabling. The running app handles commands from the bundle executable, the optional Homebrew/manual `betterdisplaycli` companion, HTTP, custom URLs, and distributed notifications. These four command transports share operations/parameters; Shortcuts is a smaller named-action interface. The bundle executable also offers `help`; unattended scripts should use an absolute executable path. HTTP may be addressed from another device using the Mac hostname. A configured token is passed as a query parameter in HTTP/custom URLs; it is stored in preferences and may appear in settings exports. URL percent-encoding and shell quoting solve different problems and both may be needed. URL access supports x-callback-url success, error, and result reporting. Incoming app-wide access is separate from per-display outgoing Control Integration. A controller, connection, permission, platform, or license restriction remains effective through every transport.
- **FreeDisplay today**: 🟡 Partial. Settings → Automation mounts `LocalControlPanel` (`Apps/OpenDisplay/Sources/SettingsView.swift:45`). Its Start, Stop, Copy Session Token, endpoint/status text, and departure teardown are explicit (`Apps/OpenDisplay/Sources/LocalControlPanel.swift:19`). HTTP binds only `127.0.0.1` on a random port, creates a 32-byte random token, limits connections to eight and lifetime to five seconds (`Apps/OpenDisplay/Sources/LocalControlServer.swift:22`). It accepts authenticated `GET /v1/displays`, `POST /v1/brightness`, and `POST /v1/reconnect-all`; requests are at most 8192 bytes, bodies at most 256, Origin/transfer encoding/duplicate headers are rejected, and the token must be a Bearer header (`Packages/AutomationSchema/Sources/AutomationSchema/LocalHTTPControl.swift:17`). This intentionally differs from BetterDisplay's LAN/query-token interface. CLI and Intents compose their own providers rather than sending all work to the GUI (`Tools/opendisplay/Sources/main.swift:61`, `Apps/OpenDisplay/Sources/OpenDisplayIntents.swift:19`). No shared full command catalog, persistent HTTP service, access toggles for each transport, configurable port, or x-callback response exists. URL recovery accepts reconnect-all aliases, while disconnect requires a display/target selector (`Packages/AutomationSchema/Sources/AutomationSchema/URLCommand.swift:59`). The disconnect confirmation flow is incomplete: the handler activates the app and returns the command, but its caller discards that return without presenting a confirmation (`Apps/OpenDisplay/Sources/OpenDisplayIntents.swift:58`, `Apps/OpenDisplay/Sources/OpenDisplayApp.swift:241`).
- **Implementation notes**: M/L. Public Foundation, Network, Security, URLComponents, and AppKit suffice for transport. Reuse one typed dispatcher with explicit command capabilities and structured results. Retain loopback/Bearer defaults; LAN reachability is a separate opt-in product decision, not required to copy a weaker token-in-URL design. Longer operations need independent operation lifetime/status rather than silently equating a socket timeout with rollback. Provider risk remains command-specific.
- **Acceptance criteria**:
  - Each exposed transport has a documented default, lifetime, authentication model, command list, and readiness state.
  - Wrong/missing token, oversized body, invalid/nonfinite brightness, unknown route, and inactive target produce machine-readable rejection without a write.
  - Stopping the service invalidates credentials; logs/exports do not leak tokens; repeated equivalent commands return equivalent semantic results.

### 2. Command grammar, selection, and truthful results — https://betterdisplay.pro/guide/integration/cli-reference/ · https://betterdisplay.pro/guide/integration/cli-examples/

- **BetterDisplay behaviour** (Free interface): CLI accepts one or more operations followed by single- or double-hyphen parameters, with optional `=value`. URL/HTTP operations occupy successive path segments and parameters occupy the query. `perform` executes valueless actions; `set` writes; `get` reads; `toggle` changes Boolean state; `feed` updates custom control state without calling its setter; `create` requires VirtualScreen type; `discard` deletes selected discardable devices without undo/confirmation. Missing discard selectors can remove every virtual definition. `help` supports general or operation/feature/parameter help. `exit`/`clear` are console-only. Compatible operations such as set/get and toggle/get combine. Device omission can target all suitable devices, so discovery and explicit selection are essential.
- **BetterDisplay behaviour** (selection/value detail): Source selectors are `tagID` (installation-specific numeric identity), `UUID` (macOS installation identity), transient `displayID`, displayed `name`, case-insensitive `nameLike`/`n`, `originalName`/`originalNameLike`, EDID `productName`/`productNameLike`, numeric `vendor`, `model`, `serial`, `alphanumericSerial`, `yearOfManufacture`/`weekOfManufacture`, `registryLocation`, and `type`/`deviceType` (`Display`, `VirtualScreen`, `DisplayGroup`). Context selectors are `displayWithMouse`, `displayWithFocus`, `displayWithMainStatus`, and `displayWithNonMainStatus`, selecting the pointer, focused-window, main, or non-main displays respectively. Target selectors are `targetTagID`, `targetUUID`, `targetDisplayID`, `targetName`/`targetN`, `targetNameLike`, `targetOriginalName`, `targetOriginalNameLike`; `targetSelf` selects self-streaming. Source and destination are not interchangeable. `value` supports integer, real, percent, on/off, or string according to feature; direct feature assignment is normally equivalent. `offset` explicitly requests relative change: a minus sign alone does not. Bare `min`/`max` request limits; valued min/max rescale input/output; explicit `value` with get asks for current value alongside bounds. Example recipes also use `feature=ddc`; accept or explicitly document this alias if implementing compatibility. Names with spaces need quoting, and substring matching can affect several devices.
- **FreeDisplay today**: 🟡 Partial with P0 defects. Positional verbs and `--json`/`--dry-run` differ from this grammar (`Tools/opendisplay/Sources/main.swift:18`). CLI has ID/alias/tag/group/main/builtin/state/numeric-CG-ID selectors, persisted identity and managed-offline recovery (`Tools/opendisplay/Sources/main.swift:86`, `Tools/opendisplay/Sources/main.swift:156`); it has no general get/set/perform/toggle/feed dispatcher, broad EDID/context selectors, unit normalization, or multi-operation contract. The dispatch catalog is authoritative (`Tools/opendisplay/Sources/main.swift:1217`), whereas `Tools/opendisplay/README.md:15` advertises get/set commands absent from it. `--help` is removed from positional arguments and falls back to `list` despite a later help case (`Tools/opendisplay/Sources/main.swift:18`, `Tools/opendisplay/Sources/main.swift:1236`). Brightness/DDC hardware failures are printed and return normally (`Tools/opendisplay/Sources/main.swift:644`, `Tools/opendisplay/Sources/main.swift:774`); several such commands ignore `--json`. `scene apply` reports applied targets while explicitly skipping brightness/disconnect/rotation and bypassing its planning result (`Tools/opendisplay/Sources/main.swift:600`). These are static defects, not runtime reproductions.
- **Implementation notes**: M. Public Foundation parser/typed schema first; feature adapters second. Unknown options must not quietly run the default verb. Preserve stable selectors, explicit multi-target intent, dry-run, per-target statuses, unsupported versus failed versus requested versus verified, and nonzero failure/partial exit policies. Do not promise a GUI safety/audit path for direct provider calls.
- **Acceptance criteria**:
  - `help`, `--help`, and `-h` produce help without provider writes; documented commands all dispatch.
  - A failed write or partially applied scene cannot look like full success in exit status or JSON.
  - Percent, signed offset, quoted Unicode name, missing/ambiguous selector, multiple targets, and stale display ID have defined outcomes.
  - Destructive bulk deletion requires explicit scope in FreeDisplay even though BetterDisplay allows unqualified discard.

### 4. Display modes, profiles, placement, and mirroring — https://betterdisplay.pro/guide/integration/cli-reference/ · https://betterdisplay.pro/guide/integration/cli-examples/

- **BetterDisplay behaviour**: Free mode controls include `displayModeList`, `displayModeNumber`, `resolution=WIDTHxHEIGHT`, exposed `refreshRate` in Hz, `colorDepth`, and `hiDPI`. Combining selectors chooses a supported mode; it does not manufacture one. HiDPI toggling requires paired alternatives. Pro `favoriteMode`/`saveFavoriteMode` use slots 1–5. `colorProfileURL`, `installedColorProfileURLs`, and `colorProfileReset` address ICC profiles; `xdrPreset`, `xdrPresetList`, and `xdrPresetReset` address supporting Apple displays separately. `connectionMode` is a physical-link format, not ICC: a listed number or `bpc:8|10|12|16`, `range:limited|full`, `encoding:rgb|ycbcr`, `chroma:444|422|420`, `hdrmode:sdr|hdr10|dolby` joined by plus signs. Omitted components retain current values; a compatible match is required. `connectionModeList` matches current resolution/rate/HDR, `connectionModeListAll` is wider and potentially unsafe, and `preferredConnectionMode` describes macOS preference. `refreshRateList` includes available VRR and hidden/NTSC timings on supported Apple Silicon connections.
- **BetterDisplay behaviour** (layout): `placement` uses logical global X/Y coordinates. Pro `moveTo` requires an anchor target and accepts `topLeftCorner`, `topLeft`, `top`, `topRight`, `topRightCorner`, `leftTop`, `left`, `leftBottom`, `rightTop`, `right`, `rightBottom`, `bottomLeftCorner`, `bottomLeft`, `bottom`, `bottomRight`, `bottomRightCorner`. `main` can set/query main; clearing it requires choosing another main. `mirror` can query, enable with one or more target displays, or disable. The comparison rates mirroring configuration/protection Pro even though the CLI mirror entry lacks that annotation. Rotation is Pro, uses 0/90/180/270 and requires framebuffer support. `notch` is Pro and only switches modes with compatible notched/notchless alternatives.
- **FreeDisplay today**: 🟡 Partial. GUI mode selection, explicit Apply and keep/revert exist (`Apps/OpenDisplay/Sources/DisplayDetailView.swift:66`, `Apps/OpenDisplay/Sources/AppModel.swift:3081`); public mode enumeration and arrangement exist (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider.swift:371`, `Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider.swift:436`). ICC enumeration/set/reset is implemented with ColorSync (`Apps/OpenDisplay/Sources/ColorProfileService.swift:35`, `Apps/OpenDisplay/Sources/ColorProfileService.swift:85`). CLI has scene arrangement and favorite membership editing, not direct mode/profile selection or five numbered save/apply slots (`Tools/opendisplay/Sources/main.swift:600`, `Tools/opendisplay/Sources/main.swift:872`). Mirroring only targets current main (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider.swift:227`). Rotation is an isolated opt-in SkyLight helper that refuses sole-active and mirrored targets (`Tools/opendisplay/Sources/main.swift:1105`). No Apple preset, low-level connection-mode, notch, or hidden-NTSC automation path exists in the dispatch catalog.
- **Implementation notes**: M for public CoreGraphics mode/layout and ColorSync command adapters; L/private for link modes, Apple presets, notch specifics, and SkyLight rotation. Preserve the existing revert workflow and identity checks. Do not infer an HDR/link switch from NSScreen EDR headroom.
- **Acceptance criteria**:
  - Query available modes/profiles before selecting; unsupported combinations fail without partial fallback.
  - Saved identifiers resolve after reconnect; a favorite edit is not reported as a mode application.
  - Mirroring names source/target explicitly, handles multiple targets, and can restore independent layout.
  - Risky link/rotation changes have a bounded verification and recovery path.

### 5. Connection, EDID, framebuffer, CEC, and diagnostic commands — https://betterdisplay.pro/guide/integration/cli-reference/ · https://betterdisplay.pro/guide/integration/cli-examples/

- **BetterDisplay behaviour**: `connected` changes display/virtual connection; physical-display management requires Pro and a compatible path. Automatic rules can reverse a request later. Pro global `disconnectAllButMain`, `connectAllDisplays` (including unlisted displays), and `swapIdenticalDisplays` provide bulk/recovery actions. `reinitialize` rebuilds native Apple Silicon connections. `customEDID` stores/gets a complete Base64 EDID separately from Pro `applyCustomEDID`, `applyFactoryEDID`, and `autoApplyCustomEDID`; disabling auto-apply, restoring factory, and clearing stored data are three different steps. `i2cEDID` and `osEDID` expose different evidence sources. Apply may interrupt image output. `framebufferBoolProperty`/`framebufferNumericProperty` select a property through specifier; `gpuDithering`, `standardFramebuffer`, `invertedFramebuffer`, `grayscaleFramebuffer`, `invertedGrayscaleFramebuffer`, and global `resetVMM7100` require applicable Apple Silicon paths. The reference does not explicitly tier every low-level command.
- **BetterDisplay behaviour** (Free diagnostic/control comparison): `identifiers` emits JSON for displays/virtual screens/groups; `identifier` reads any supported identity field. Reports include detailed `displayInformation`, decoded/raw `EDIDReport`, `appleBrightnessReport` (capability/state/adaptation/HDR/EDR/boost where available), parsed/probed `ddcCapabilities`, raw `ddcCapabilitiesString`, `DPCDReport`, `CECReport`, and `DSCReport` (PPS plus decoded fields). `rawDPCD` emits 16-byte hex rows, supports start+size such as `0x1000+4K`, suppresses all-zero rows unless `+0` is present. `sendCEC` uses Apple Silicon DisplayPort AUX/DPCD CEC tunneling on supported HDMI devices. Commands: volumeUp/down, mute, standby, wake, input, select, up/down/left/right, rootMenu, setupMenu, contentsMenu, exit. `volume+X`/`volume-X` repeat steps; `input`/`input:mac` requests the Mac input; `input:2`, `input:1.2`, or `input:2.0.0.0` specify physical addresses. `CECAddress` defaults to tv and accepts 0–15: tv, recording1/2, tuner1, playback1, audioSystem, tuner2/3, playback2, recording3, tuner4, playback3, reserved1/2, freeUse, broadcast in numeric order. Probe reports must tolerate absent fields.
- **FreeDisplay today**: 🟡 Partial. CLI disconnect/reconnect/recover are wired to a gateway; OS/private provider selection and managed-offline enumeration are present (`Tools/opendisplay/Sources/main.swift:61`, `Tools/opendisplay/Sources/main.swift:106`). OS EDID decode/export exists (`Tools/opendisplay/Sources/main.swift:822`). The advanced GUI validates/imports/exports EDID and HiDPI plans but explicitly does not install them (`Apps/OpenDisplay/Sources/AdvancedDisplayToolsView.swift:37`). That is not live EDID override. Diagnostic bundles collect topology, local audit/history, redacted settings and system reports (`Providers/CoreGraphicsProvider/Sources/CoreGraphicsProvider/DiagnosticsBundle.swift:74`), but not typed CEC/DPCD/DSC/Apple-brightness reports. Local control explicitly declares TV/AVR/CEC unimplemented (`Apps/OpenDisplay/Sources/LocalControlPanel.swift:35`). Arbitrary framebuffer writes, hardware reinitialization, CEC tunneling, VMM7100 reset, factory EDID restoration and live EDID auto-apply have no dispatcher/provider implementation.
- **Implementation notes**: L. CoreGraphics supports enumeration and some arrangement/recovery; IOKit registry reads support OS EDID evidence. IOAVService/DCP/framebuffer/adapter manipulation is private or undocumented and needs distinct provider boundaries. Never substitute EDID export for application. Diagnostic parsing can be public/offline once raw evidence is available.
- **Acceptance criteria**:
  - Offline displays remain addressable; refusal to remove the last usable display survives every automation surface.
  - EDID storage, validation, apply, auto-apply and factory recovery are distinct operations with identity checks.
  - Reports identify evidence origin, unsupported fields and units; a CEC send does not claim TV completion.
  - Low-level mutations stay unavailable when capability probing fails.

### 6. Virtual definitions, groups, and configuration protection — https://betterdisplay.pro/guide/integration/cli-reference/ · https://betterdisplay.pro/guide/integration/cli-examples/

- **BetterDisplay behaviour**: Preconfigured virtual creation is Free; custom configurations and associations are Pro. `create` supplies missing identifiers with defaults/random values as appropriate. Configuration fields are `virtualScreenName`, `virtualScreenSerial`, `virtualScreenVendorNumber`, `virtualScreenModelNumber`, `aspectWidth`, `aspectHeight`, `sizeInch`, `multiplierStep`, `limitMultiplierSize`, `multiplierMinWidth`, `multiplierMinHeight`, `multiplierMaxWidth`, `multiplierMaxHeight`, `flipped`, `virtualScreenHiDPI`, `useResolutionList`, and comma-separated `resolutionList` of WIDTHxHEIGHT. Existing device selectors are separate from fields being renamed. No unspecified numeric defaults should be invented from the example 12:10 screen.
- **BetterDisplay behaviour** (Pro): Groups distinguish `enabled` from read-only `active`; `activationPolicy` values are always, allMembersPresent, anyMembersPresent, anyTwoMembersPresent, anySyncSourceWithTargetMembersPresent. `synchronization`, `layoutProtection`, and `uiScaleMatching` are independent switches. Membership/relationships are created in the GUI before CLI automation. Protection parameters capture current resolution, refresh rate, HDR, rotation, main status, SDR/HDR ICC profile and SDR/HDR connection color mode; names are `protectResolution`, `protectRefreshRate`, `protectHDR`, `protectRotation`, `protectAsMain`, `protectSDRProfile`, `protectHDRProfile`, `protectSDRColorMode`, `protectHDRColorMode`, `protectAll`. Main protection requires current main; SDR/HDR variants require the corresponding current state; connection-mode protection requires Apple Silicon. protectAll enables every currently applicable protection.
